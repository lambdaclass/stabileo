### Verification

- [VERIFICATION.md](VERIFICATION.md): testing philosophy, fuzzing and invariants
- [security/THREAT_MODEL.md](security/THREAT_MODEL.md): assets, actors and trust boundaries
- [security/AUDIT.md](security/AUDIT.md): security audit findings and their status
- [BENCHMARKS.md](BENCHMARKS.md): validation coverage against analytical and reference solutions
- [verification/CERTIFY.md](verification/CERTIFY.md): result certificates: rigorous error bounds on solver output, proved sound in Lean
- [verification/ASSEMBLY.md](verification/ASSEMBLY.md): cross-path assembly oracle: every path that builds the same K, loads, M or K_G compared entry by entry on random models
- [verification/KANI.md](verification/KANI.md): Kani proofs of the element kernels, interval rounding and sparse index code, and how to run them safely
- [verification/SYMBOLIC.md](verification/SYMBOLIC.md): frame element matrices derived symbolically from first principles and checked exactly against the Rust kernels
- [verification/DESIGN_EXAMPLES.md](verification/DESIGN_EXAMPLES.md): every design check, clause by clause, against published worked examples (AISC, SCI, JRC, INTI-CIRSOC), with the discrepancies found and their root causes
- [verification/FEATURE_MATRIX.md](verification/FEATURE_MATRIX.md): which model features each analysis supports or refuses, generated by a test that checks every pair against an independent reference
- [verification/SECTIONS_CONNECTIONS.md](verification/SECTIONS_CONNECTIONS.md): section properties against exact forms and an independent FE solve, catalogue and material data against producer tables and standards, connection checks against published worked examples
- [verification/LOADS.md](verification/LOADS.md): load generation and combinations checked clause by clause against the CIRSOC texts and published worked examples
