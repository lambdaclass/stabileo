# Steel stations and shear reports retain their physical meaning (2026-11-14)

PR #2080 round 10 found that the legacy tuple adapter stored normalized station `t` as physical station `x`. Brace intervals are expressed in metres. A ten-metre member braced at five metres therefore located the tuple at `t = 0.8` in its first interval instead of its second. The retained regression uses a varying first-interval diagram and a uniform second interval: the reviewed code reports flexural capacity 114.33575351302306 kN·m instead of the physical-station control's 91.46860281041846 kN·m. These values come from the checked IPE 300 fixture and WASM checker, not an engineering reference value.

The adapter now converts tuples once using the element diagram length. Missing, nonpositive or nonfinite lengths produce an unavailable physical coordinate; the common parameter preparation withholds computed Cb credit for that coordinate. It never substitutes the possibly longer chain buckling length for an unknown element length. Full checks, interaction, search screening and certification use the same converted concurrent demands. Certification no longer rebuilds a separate tuple list. Grouping through `ConcurrentDemand.fromTuples` also preserves each combination's actual end moments.

The reported shear finding was partly a mismatch in the summary, rather than a stale shear calculation. In pipe-rack e15 the reviewed snapshot has strong-axis `shear.Vu = 0.796728424`, capacity 481.14 and ratio 0.001655918078. Its separate weak-axis check has `shearWeak.Vu = 1.138370238`, capacity 1741.5 and ratio 0.0006536722583. Those are different physical components with different resisting areas. Feeding the larger weak-axis demand into the web check would obscure that distinction. The independently retained check and its combination were correct; the top-level `Vu` incorrectly copied the envelope over both components. It now comes directly from the selected strong-axis shear result. Weak-axis shear remains separately checked and reported.

The three steel snapshots were regenerated through `make snapshots-update FILE=src/lib/results-snapshot/__tests__/snapshot-design.test.ts FILTER=design-steel`. Only the pipe-rack snapshot changes: sixteen top-level `Vu` summaries. The per-axis demands, capacities, ratios, statuses, combination labels and solved forces remain identical. The [generated comparison](2080-round10-steel-diff.json) records every changed field against reviewed head `8d1f05bfac` under the unchanged snapshot comparison rules. The tuple-only Cb path is not exercised by these corpus snapshots.

The new tests exercise the ten-metre model through physical packets and legacy tuples, both moment signs, full and screened checks, the profile candidate entry point, both sides of the brace and the brace itself, endpoint stations, unknown/invalid lengths and correct first-interval answers. Shear tests separate the two axes and their governing combinations in either input order, with either axis carrying the larger demand, through tuple, packet and model verification entry points. Solved planar and spatial models use both linear and nonlinear WASM results. These are TypeScript orchestration changes over a common spatial force contract; there is no native counterpart of the tuple adapter or the summary reducer, and no native formula changes.

Commit A adds ignored reproducers with the requested known-wrong markers in their Vitest names; `RUN_KNOWN_WRONG=1` enables them. On the reviewed production code, 35 assertions fail and four correct-input controls pass. Commit B removes the ignores and applies the fixes. The strengthened concrete tests assert the loaded axis's own Cm via `flexureAxis`, independently check the unloaded axis, and retain the existing planar/spatial and linear/nonlinear controls. The manual steel interaction helper uses the same physical strong-axis channel as whole-element checks. The saved-project test now contains concrete and steel members with distinct material identities and expects the secondary-slenderness record explicitly.

The existing SA-2026-066 is listed in the blog's status notes and summary table in all six locales, retaining its draft status. No advisory is created or renumbered. The newly corrected coordinate adapter and mixed-axis summary overwrite exist only on the unmerged branch; `origin/main` at `08fa96822e7e71b63b60795bf0b3c9d927a99406` has neither path. The previously documented main Cb and concrete Cm defects retain their existing advisory records. No tolerance, baseline, numerical assertion or engineering limit is loosened.
