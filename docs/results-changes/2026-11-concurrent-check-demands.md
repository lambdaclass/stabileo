# Concurrent checks retain governing demands (2026-11-13)

Review of PR #2080 found three defects in the unmerged concurrent-demand implementation. Held D.2 checks have nonfinite utilization, and the reducer replaced an earlier maximum tensile force with a later smaller force. The interaction API stores absolute moment magnitudes, so testing that magnitude's sign always selected the positive-moment flange. Finally, the steel adapter inferred behaviour exclusions from zero member axial summaries, erasing interior axial forces that the station data retained.

Each individual steel check now retains its own result and combination. Nonfinite utilization ties use the check's actual demand, and normalized rows read the selected check's demand. Strong-axis flexure attribution follows the governing utilization, including its combination's Cb, rather than the largest moment. A shared flange-selection function reads a signed source-moment accessor for single, batched, full-member and certified checks. Explicit member behaviour masks station packets and legacy tuples at the behaviour boundary; checking never infers an exclusion from an envelope.

CIRSOC 201 aggregates certificate acceptance and utilization bounds across every concurrent case. A missing or refused later certificate cannot inherit the first case's acceptance. Its engine-recheck schema uses a certificate object and a disagreements array; the steel schema separately provides certified, certifiedOk and disagrees booleans and already gates every case.

The SA-2026-064 replay is regenerated through `make replay.advisory.steel-cb`. Both corrected records attribute flexure to combination 1, whose utilization governs even though combination 2 has the largest moment. The replay validates each before witness against its independent oracle and recorded understatement, its single-combination control, and its silent or warned status. Release exposure is restricted to the explicitly documented tags. The original fixing commit remains recorded, with SHA-256 hashes identifying the actual source files used for the replay including these review corrections.

Snapshots are regenerated only through `make snapshots-update FILE=src/lib/results-snapshot/__tests__/snapshot-design.test.ts`. The generated [review diff](2080-concurrent-check-demands-diff.json) records every changed field relative to the reviewed branch. In particular, maximum tension is restored in tower elements e9, e10, e11, e14 and e15 and pipe-rack element e100. No analysis kernel, fixture, tolerance or assertion is relaxed.

The new expected-failure reproducers in commit A cover held tension with a different interaction combination, both source axes and both interaction entry points for negative moment, both signs of an interior axial force through station, tuple and packet adapters, flexure attribution, and later refused or missing concrete certificates. Correct-input controls cover nonnegative moments, explicit axial behaviours and all-certified acceptance. These are TypeScript orchestration paths over the public WASM kernels; there is no native counterpart of the orchestration. Planar and spatial, linear and nonlinear results reach the same station-demand contract.

The judge regression came from a test fixture inheriting `area: design` from whichever registry entry sorted first. A design entry cannot explain an analysis reaction in the snapshot gate. The fixture now explicitly describes an analysis entry; its analysis-condition assertions remain unchanged. Registry design entries retain their design scope.

The newly reported demand and flange defects are branch regressions. The silent origin/main Cb witness is already covered by SA-2026-064; no new advisory is introduced.
