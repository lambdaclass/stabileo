# Planar nodal components at the solver boundary

The native and direct WASM decoders now apply the same planar nodal load rule as project intake. In a record that supplies all six components, the solver uses `fx`, `fz` and `my`, and requires exact zero for `fy`, `mx` and `mz`. Shorter records retain the legacy `fy` and `mz` aliases. A supplied `mx` must always be zero. The named decoder accepts the saved load identifiers `id` and `caseId` as metadata. The app selects cases before building solver inputs. The identifiers contribute no force or moment and are absent from the canonical input hash. Unrecognized keys also cause a parse refusal. Use the spatial solver when applying an out-of-plane load.

A planar solve could previously succeed after omitting an applied `mx` couple. A complete vector with zero padding can now reach the same solve as the equivalent canonical planar load. Both changes occur at decoding, and the registry covers solve success. The `native:planar-nodal-vector` evidence applies to a raw solver record with the complete component layout, an unsupported component key, or saved load metadata. The project intake change has its own registry entry.
