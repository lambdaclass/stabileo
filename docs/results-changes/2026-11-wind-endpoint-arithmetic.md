# Wind member endpoint arithmetic (2026-11-16)

Rerun analyses that the unmerged #2222 interval validation refused at rounded member endpoints. Main's existing wind integration tests exposed this branch regression in native 2D and 3D linear and nonlinear analyses. Web Unit 4/8 failed for the same reason. The generated wind intervals are supported in width: their endpoints differ from the solver's geometric lengths because of norm evaluation or translated coordinate arithmetic. The checked-in cubic-grid example ends at `0.5142956348249517` on native length `0.5142956348249516`; the taper-crossing example ends at `1.500018749882814` on length `1.5000187498828135`.

A shared native mapping now recognizes an overhanging endpoint only if it equals the alternate hypot norm of the member's coordinate differences, or reconstructs the exact stored end node through the member direction and coordinate addition. Recognition also requires the discrepancy to fit the norm arithmetic budget `4 * epsilon * L`. Coordinate aliasing on coarsely translated models therefore cannot authorize a substantial change of length. This arithmetic bound does not change the existing relative interval limit. An overhang beyond those geometric equivalences remains invalid, including a next-representable overhang on the exact member from zero to three. Negative, reversed, non-finite, collapsed and sub-limit intervals retain their strict validation.

For a recognized source endpoint `B` and native length `L`, the mapping uses `r = B/L`, `u = x/r`, and `q_native(u) = r*q_source(r*u)`. All intensity components and the start coordinate use this same change of variables. The intensity mapping must retain its resultant and first-moment density combinations within arithmetic roundoff; otherwise the original interval refuses. This prevents multiplication rounding from changing a small resultant between nearly cancelling large endpoint intensities. The end is represented as the complete native endpoint. This retains the resultant and the first moment in source coordinates within floating-point evaluation error; the physical coordinates differ only through the recognized endpoint arithmetic. It does not discard a load fragment or replace a distributed load by nodal forces. Canonical intervals pass the existing strict predicate before solving; assembly, force recovery and independent totals use the same mapping. Saved member loads therefore remain within their recorded member length.

The regression matrix covers native and WASM linear, prepared/session, P–Delta, corotational and fiber entry points, planar and spatial models, axial and transverse loads, translated and sloping geometry, supported controls and distinct overhang refusals. Main's three previously failing wind tests pass unchanged. The fiber acceptance test now checks its prescribed applied-force vector and balancing reactions. Opposing transverse endpoint intensities have a numerically significant analytical couple whose reaction wrench is checked, so a silently dropped couple cannot pass with a zero force resultant.

This endpoint refusal was introduced on the unmerged branch. It is not evidence of a new silently wrong result on main or a release, and no advisory is added. The earlier main exposure recorded in the preceding worktree handoff is unchanged. Surface-normal translation at `2^50` and non-finite values in compensated summation remain deferred to #2262.

The registry applies to members with explicit distributed-load endpoints (`partialDistributedMemberLoads`). A full-length load with no explicit endpoint has no overhanging endpoint to map. This entry cannot explain unrelated displacement, reaction or member-force changes in such a model, including the historical cable-stayed bridge. The engine mapping and its arithmetic and geometry limits are unchanged by this registry correction.

## Decimal stations on translated and rotated members (round 15, #2223)

A member from station `0.4` to `0.6` has stored geometric length `0.19999999999999996`; a load ending at nominal station `0.2` was refused. The same failure reaches the rotated uniform and concentrated-patch fixtures in #2207. Native and WASM paths now use the existing shared endpoint mapper with an additional geometric certificate: the excess length must lie strictly inside the projection of the two stored nodes' floating-point rounding cells onto the member direction. Each cell radius is half the smaller distance to its adjacent representable coordinates. This handles uncertainty in both stored stations and rotating the member, rather than depending solely on reconstructing the final coordinate in one arithmetic order.

The existing `4 * EPSILON * length` cap, density-preservation checks and relative geometry limit are unchanged. Coordinates and intensities continue through the same shared mapping in validation, assembly, independent applied-force accounting and recovery. For the translated axis-aligned witness, the adjacent endpoint below `0.2` and `0.2` solve; the adjacent endpoint above `0.2` refuses. Origin-based genuinely out-of-member endpoints and unsafe intensity remaps still refuse. No blanket endpoint clamp is added.

The new native and WASM matrix covers axial and transverse loads, rotations in both directions, 2D and 3D, linear and nonlinear analyses, and prepared/session paths. The unchanged concentrated-live tests retain their original signed diagrams and displacement oracles. This fixes a branch availability regression; it does not establish a silently wrong main or release result.

## Web adapter endpoint validation (round 16, #2223)

The adapter rejected a wind load ending at `4.000000000000001` on the member between stored stations `1000.1` and `1004.1`, even though the shared native endpoint mapper accepts it. Adapter validation now calls that same Rust geometric certificate through a WASM export before checking the interval. It uses the actual flexible member endpoints, including spatial offsets. The source interval and intensities remain unchanged on the wire; the solver still performs its existing coordinate and density mapping together and can refuse a density mapping that would lose a resultant. There is no second TypeScript implementation of the endpoint certificate and no relaxed tolerance.

The adapter tests cover planar and spatial load representations, linear, prepared/session, P–Delta, corotational and fiber solves, the existing rounding cap and the adjacent out-of-cap endpoint, and a full-span control. Native endpoint and density-preservation tests remain unchanged. An unavailable endpoint kernel cannot authorize an overhanging interval.
