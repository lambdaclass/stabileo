# Interior displacement and rotation retain member couples (2026-11-15)

Issue #2143 affects displayed interior displacement. The TypeScript hover helper independently reconstructed a fixed-end particular solution using only point forces. Its WASM deformed-shape request also narrowed each point-load record to `[a, p]`, discarding `my`. The engine's span-rotation recovery already integrated couples correctly, but the public deformed-shape function constructed that recovery with an empty couple list.

The reported fixed–fixed witness is reproduced independently: length 5 m, EI 20,000 kN·m², and a 6 kN·m couple at 2 m. At 1 m the old hover and public native/WASM shape return zero; integrating the piecewise beam equations subject to zero end displacement and rotation gives −3.6e−6 m. The reproducer parent is exact origin/main `44966b6e75f72ce268ec87798d5cd880a6dba144`. There is no warning at the recovery API. The coordinator assigned [SA-2026-070](../advisories/SA-2026-070-interior-member-couples.md); PR #2170 is pending merge and release.

All transverse recovery now uses the existing engine member solution. A single `MemberLoad` enum and exhaustive match integrate force, distributed load, and couple contributions for displacement and section rotation. The public shape accepts complete point-load records; legacy `[a, p]` requests remain accepted. Exhaustive record destructuring requires a deliberate decision when the engine's point-load or distributed-load record gains a field. TypeScript delegates both planar hover recovery and both planes of the spatial member curve to this engine implementation. The hover rotation reads the same recovered section rotation instead of interpolating end rotations. Canvas, hover and education callers share the conversion from published drawn-axis loads to solver-axis loads, including the sign of a couple on reversed and upward members.

Commit A contains ignored reproducers with the reason `known wrong result: #2143`. Enabling them on the unchanged parent fails 83 web cases and the native public-shape case. Eighteen web controls and two native controls pass, including actual 3D linear and P-Delta solutions with a split-member nodal couple in each bending plane. The 3D span-point-load model contains forces only; it has no interior couple field. The split-node equivalent tests the same physical beam without inventing a new unsupported load component.

The static second-order teaching sketch also used to pass no member loads at all. It now forwards every member load through an exhaustive TypeScript switch with a `never` check, and includes interior deflection when setting its drawing scale. Buckling modes explicitly omit static member loads. Three additional teaching-sketch reproducers failed before that caller fix.

Loaded recovery with missing, nonfinite, or below-cutoff EI is now explicitly refused instead of silently returning the load-free interpolation. The existing EI cutoff is unchanged. Boundary tests keep the response in the elastic range by scaling the synthetic couple with EI; load-free and axial-only controls still recover their curve. Six direct parent-TypeScript replays fail the new refusal expectation and pass with shared recovery.

The independent web oracle integrates piecewise polynomials and solves the end conditions with elimination. It covers both signs, several couple positions including near the ends, every end-release combination, point and partial trapezoidal loads, rotations, inclined axes, the existing EI boundary, and Euler–Bernoulli and Timoshenko cantilever controls. The native oracle uses the separately derived fixed–fixed couple solution. Actual linear and P-Delta results feed recovery in both runtimes.

Native/WASM shapes without couples are exactly unchanged in the 24 saved controls in [the parent-shape record](2143-no-couple-shapes.json): 504 stations with nonzero end motion, all end-release combinations, and point/full/partial distributed loads. Moving TypeScript consumers to the engine also replaces the old Simpson approximation for partial loads and the duplicated full trapezoid formula. A direct replay of the original TypeScript helper against the independent oracle fails both full and partial trapezoid cases, while the shared engine passes. Those TypeScript-only no-couple values may therefore change to the engine's exact curve; this is included in the saved-project notice's member-load scope. Nodal displacements, member forces and solver tolerances do not change. Spatial serviceability checks already read `memberLocalCurve` and now use this shared recovery too.

Reopen saved projects with member loads, rerun their analyses, and review displayed deflections, rotations and any serviceability decisions that use the recovered curve. No results snapshots are regenerated: this change affects recovered display/check fields, not the nodal analysis records stored by the snapshot fixtures.
