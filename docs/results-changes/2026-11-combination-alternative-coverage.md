# Cover shared alternatives and preserve roof load inputs

A rule that matched stand-alone wind and seismic cases could generate a combination that skipped their shared alternative set. Each generated combination now selects one case from every active shared set. A directional pick can satisfy its symbol in place of a stand-alone case. Generation stops with a diagnostic if the directional constraints prevent any eligible case in a required set from being represented. In the regression model, the shared set carried downward loads of 2 and 4 kN and the stand-alone cases carried 8 and 16 kN. With both factors set to 1, the extra stand-alone combination gave a 24 kN vertical reaction. The valid combinations give 18 and 12 kN.

Auto Loads uses the replacement scope and the surviving loads when assembling its case list. A retained roof-live case participates even if its alternatives key matches a planned floor case. The shared key still governs exclusivity when both symbols are active. In the regression model, the plan supplies 3 kN of roof live load and a manual case adds 5 kN. At a factor of 2, the reaction changes from 6 to 16 kN. An old unbound case whose loads are removed by replacement contributes no load.

The rule editor uses separate inputs for physical snow and flat-roof companion snow. Changing a factor preserves its basis and leaves the other basis available for independent editing. Editing a flat-roof snow factor to 2 previously selected the 3 kN physical case in the regression model. It now selects the 5 kN flat-roof case, giving a reaction of 10 kN instead of 6 kN. Template import already preserves this basis on the current main branch.

Review the affected project rules against their original templates, especially if a snow factor has already been edited. Regenerate affected Auto Loads and combinations, including generated composite cases, then rerun the analyses and envelopes. Saved case-ID factors require regeneration to pick up these changes.
