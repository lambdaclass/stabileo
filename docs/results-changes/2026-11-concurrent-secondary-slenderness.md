# Concrete checks retain secondary slenderness (2026-11-14)

PR #2080’s concurrent aggregator took `slenderSecondary` from the governing biaxial check. Each case computes secondary slenderness before deciding whether biaxial verification is needed. Consequently a secondary design moment at or below the existing `0.01` cutoff could leave the aggregate without its computed result and its calculation memo. Even when biaxial verification exists, its governing utilization need not govern secondary amplification.

The shared concurrent-verification boundary now selects secondary slenderness directly from every case that computes it. It prioritizes a slender result, then larger amplification, then larger slenderness relative to its own limit, then larger amplified moment. The selected result retains its complete calculation steps. Neither biaxial availability nor its governing combination participates in that selection. Individual case demands, reinforcement, checks, certification and overall status are unchanged. Primary-axis selection is unchanged.

A minimal witness uses a rectangular column or wall with `b=0.4 m`, `h=0.6 m`, `fc=30 MPa`, `fy=420 MPa`, cover `0.025 m`, stirrup diameter `8 mm`, unsupported length `4 m`, axial force zero, primary moment `20 kN·m` and secondary moment `0.009 kN·m`. The existing slenderness calculation returns `klu_r=33.333333333333336`, limit `22`, `isSlender=true`, amplification `1`, and amplified secondary moment `0.009 kN·m`. On the reviewed branch the individual case retains that result, but the aggregate returns `undefined` and omits the secondary-axis memo. The corrected aggregate retains the exact computed result and memo. These values are runtime reproducer observations, not design recommendations or independently supplied code limits.

The runtime comparison loaded origin/main `2e8a4f65f743b23949b995e9ddc9727ad008e225`’s TypeScript source tree separately inside this worktree, using this worktree’s existing WASM artifact. Main’s direct column and wall verification retains secondary slenderness at moments `0`, `0.009`, `0.01` and `0.011`; main’s auto-verification retains the low-moment column memo that this branch dropped. This is an unmerged #1316 regression, with no new main/release advisory. The kernel was not changed by this correction.

Commit A uses Vitest expected-failure markers tagged #1316; Rust ignore attributes do not apply to TypeScript. Enabling the new cases on the production parent yields 60 failures and 11 passing controls. Coverage includes columns and walls, both section axes and CIRSOC editions, below/at/above the biaxial cutoff, absent length, short/slender boundary, reversed input order, and a slender/short tie in amplification. Planar and spatial one-member models pass through linear and P-Delta WASM solves to auto-verification, unified verification and full design, with endpoint and station inputs. This CIRSOC orchestration accepts 3D result records; the planar witnesses use planar geometry and loading through that supported API. There is no native implementation of the TypeScript aggregator, and the app’s 2D result store does not call it.

The certificate tests separately exercise missing certificates, refused certificates and shear disagreements. Both certificate-absence cases use an empty disagreements array. On the historical production parent before the certificate fix, those two cases and the separate disagreement case fail while the all-certified control passes.

Committed design snapshots are checked without update mode. This correction restores reporting at the aggregation boundary; it changes neither a design formula nor an engineering tolerance. No snapshot baseline or assertion is loosened.
