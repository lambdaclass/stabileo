# Atomic member splits and load-conserving geometry (2026-11-16)

A manual member split now computes its nodes, sections, member properties, load fragments and identifiers in temporary containers. All load validation finishes before the model or undo history changes. Refusal leaves the complete saved model and identifier counters unchanged, including variable sections.

Distributed loads must retain the geometry on which their coordinates and intensities were defined. Previously a nominal child span could be stretched to its rounded geometric length while retaining its intensities. On the reported nominal span of `4/3` generated as `1.375`, a constant load's resultant increases by 3.125%. An implicit full-span endpoint in main's older splitter has the same problem. First moments can change too.

This round-9 behavior is superseded by [generated member cuts](2026-11-generated-member-cuts.md), which restores ordinary translated and rotated models using measured geometry and conservative integral mapping. The round-9 shared web remapper required exact equality between the source span and generated child length. It checks every child before clipping, including unloaded children whose changed geometry could shift a later load. It translates coordinates without rescaling, and retains the existing interval checks. A discrepancy, including a one-ULP discrepancy, refuses the remap. This is deliberately conservative: coordinate translations, inclined geometry and subdivision can cause an otherwise valid member to be refused. Moving the model nearer the coordinate origin or choosing representable cut positions may make the split representable. No interval limit or numerical acceptance tolerance was relaxed. Native analysis of an unchanged member is unaffected.

Rerun analyses that subdivide loaded members: manual edits, analysis subdivision, variable-member expansion, planar second-order refinement, plastic collapse and Maxwell section evaluation all reach this remapper. Full and partial distributed loads, axial loads and every spatial load component share the guard. Tests check resultant and first moment for accepted rounded cut positions and refusal for inconsistent geometry. A refused manual edit leaves the original load on the original member.

Planar combination assembly also now propagates arithmetic errors instead of treating them as an absent combination. Earlier branch code could return a successful envelope containing only the other combinations. Checked native and WASM consumers share the fallible implementation; compatibility functions returning `Option` retain contained refusals as `None`; the round-15 non-finite-input diagnostic behavior is described below. Spatial combinations keep their refusal and report the established overflow diagnostic before recovery. The original overflow and summary-range assertions remain unchanged.

Recheck saved combination sets from earlier versions of this branch when factors overflowed. The combination omission was introduced by unmerged interval-validation work; it does not establish a main or release advisory. The compensated applied-force notice now excludes models without structural stiffness, while continuing to cover every analysis history with members, shells, connectors or springs and applied actions as qualified below.

The opposing-endpoint axial integration cancellation defect is present on main and remains outside this fix, as requested in #2223. It is recorded with a main-kernel replay in the worktree handoff for coordinator triage. No advisory is introduced here.

## Retained native combination diagnoses (round 15, #2223)

The planar compatibility API returns `Option`, which previously discarded any error from the shared checked combination implementation. A non-finite imported member force therefore yielded `None`, losing the established conservative second-order diagnosis for a case without a screen. It now returns an explicit error diagnostic record with empty displacement, reaction and member-force collections and no result summary. The checked native and WASM APIs continue returning an error. Both paths use the same second-order screen calculation; non-finite refusal records are refused when reused in combinations or envelopes. Finite combination values retain their answers, and arithmetic overflow retains the existing refusal behavior.

The compensated-force notice now requires structural stiffness and either applied actions or an analysis history that produces forces. Unknown histories remain conservatively included, and editing loads away does not erase notices for stored force results. Nonzero nodal forces are identified explicitly. Member loads, surface/edge loads, generated loads, settlements and explicit self-weight remain covered. Opening a project passes Basic’s separately stored self-weight toggle into the same feature assessment; PRO uses its saved gravity rule. An unloaded modal frame no longer receives a force-summation notice. Registry field scope remains limited to equilibrium, diagnostic codes and solve availability.

## Invalid saved intervals and visible interval refusals (round 16, #2223)

The planar compatibility combiner's diagnostic fallback is now gated by the existing saved-load interval validator. A NaN or infinite interval endpoint previously qualified for the non-finite-force fallback and produced an empty diagnostic result where the compatibility API promises no result. Invalid intervals now return `None`, even when an unrelated force is also non-finite. A valid interval with a non-finite member force still retains the conservative diagnostic record; checked native and WASM combinations and envelopes still refuse. Tests cover both planar distributed channels, both compatibility entry points, checked combinations, envelopes, the interval-limit neighbors, and unchanged finite answers. Spatial and WASM saved-result boundary controls retain their existing refusals.

Interval errors have a dedicated type. The shared planar solve preparation and spatial load-refusal handler return their localized messages through synchronous and asynchronous solve APIs. The direct input builders continue to throw on invalid loads. The generated-beam sweep contains zero-width loads, so its driver now verifies these refusals explicitly instead of aborting before testing the other models; valid-model comparisons and their tolerances are unchanged.

A supported source model can also generate an influence-line zone narrower than the existing interval limit. The shared influence document builder now returns a warning document with the refusal reason and no numerical tables or comparison instead of throwing out of document construction. It does not discard a zone or approximate its contribution. Beam 22 of the existing deterministic sweep reproduces this case. The influence loading panel and direct influence APIs retain their explicit refusal behavior. Analytic integration of arbitrarily narrow influence zones is outside this change; it would require a separately verified integration path. These branch refusal corrections establish no new silently wrong result on main or a release.
