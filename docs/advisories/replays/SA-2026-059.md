# SA-2026-059: web cable replay on origin/main

## Method and retained evidence

A detached `../cable-replay` worktree was created with `git worktree add ../cable-replay origin/main`.
`make wasm` built its own engine; `make web.deps` installed its web dependencies. No WASM binary
was copied from the fix branch. The main WASM cache key was `f0eb71949a146dc1261b21024e558a2b`.

The [Vitest replay source](SA-2026-059.test.ts) creates models through `modelStore`, imports the
store wiring, obtains `centerlineInput`/`dynamicInput` or the consumer's own builder and calls
the actual WASM wrappers. It executes the actual `handlePDelta` and `forgetPDelta` function
bodies from `ProAdvancedTab.svelte`, using TypeScript transpilation and a scope containing the
real store, wrapper, amplification and diagnostic functions. No WASM result or diagnostic is mocked.
The [JSON record](SA-2026-059.json) retains the observed axial forces, nested diagnostics and
`knownIssueResultDisposition` outputs. The [fixed-build replay](SA-2026-059-fixed.test.ts) checks
that the same inputs retain cable identity and are refused after the fix.

This is a Node/Vitest store-to-WASM replay plus inspection of the Svelte rendering, not a browser
screenshot or an execution of an old release binary. Background certificate computation was not
part of this replay. It does not establish a certificate for the physical cable model.

## Fixtures and measured magnitude

The base model has nodes `(0, 0, 0)` and `(0, 0, 3)`, a frame and a cable sharing those endpoints,
a clamped lower support, and a downward upper nodal load of 10 kN in case 1. The cable is a stored
truss member with `behaviour: cable`, no pretension and no self-weight. Both members initially
use the store's default material and section. The measured solver properties are E = 200000 MPa
and A = 0.0068998265206363625 m²; the retained shortening record includes all section properties.
These are read from the replay, not independently assumed section-table values.

- **Loaded/unbraced:** all upper translations and rotations are free.
- **Loaded/laterally held:** upper X and Y translations are held; Z translation and rotations are free.
- **Shortened:** all upper translations are held, rotations are free, and support `dz = -0.00001 m`.
  The same 10 kN nodal load remains on the held node. Both endpoints satisfy main's fully braced
  second-order screen, so there is no #1551 warning. Three rotational DOFs remain free.
- **Concrete creep:** the parallel frame alone is assigned a new H-30 material with E = 30000 MPa,
  ν = 0.2, strength 30 MPa and weight density 25 kN/m³. The panel's `concreteMaterials` filter
  selects that material; RH = 60, h0 = 200, t0 = 28, cement N, step 365 days are passed to `creepSteps`.
- **Pushover:** the loaded/unbraced model additionally has an upper X load of 1 kN. The panel's
  `plasticInput3D` and `plasticForSolve` helpers supply capacities; the existing-load pattern is used.
- **Moving:** the unloaded moving-load base, frame as the path, a single 10 kN axle, and a 3 m step
  give just the two endpoint positions. This is a small path replay, not a sweep or benchmark suite.

The shortened P-Delta cable reports −4.599884347090908 kN at both ends. The returned `results`
have no diagnostic array; the nested `linearResults` diagnostics are only `dense_lu` and
`residual_ok`, with no warning or error. The actual panel handler leaves `solveError = null` and
`pdeltaRefused = null`, records `converged = true`, `stable = true`, B2 = 1 and publishes the
compressed cable result to `resultsStore.pdeltaResult3D`.

On the load-driven fixture the generic-bar solutions give cable −5 kN and frame −5 kN. The
normal automatic cable solve gives cable 0 kN and frame −10 kN: all the external axial load goes
through the frame once the cable slackens. Thus the frame's compressive demand is halved by the
substitution in this fixture. The correct cable compressive resistance is zero by its tension-only
law; no percentage error relative to zero or universal model correction is claimed.
