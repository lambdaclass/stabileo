# Performance audit, October 2026

Measured 2026-10-28 (laptop, production), 2026-11-01 and 02 (GitHub runner against production) and
2026-11-01 (local build of `main` at `a85a376cb`). Related: #734. The checks that keep these numbers from getting
worse are in [README.md](README.md); the work this audit points to is in #1073 and #1072.

## Method

- Lighthouse 13.5.0 (CLI, pinned in `web/lighthouse/`), Playwright's Chromium, headless, simulated
  throttling, through `web/scripts/perf-lighthouse.mjs`.
- 2026-10-28: an 18-core Apple Silicon laptop under shared load (load average 11 to 22), median of
  3 runs, mobile only.
- 2026-11-01 and 02: a GitHub-hosted `ubuntu-latest` runner, `.github/workflows/performance.yml`, median
  of 5 runs per URL, mobile and desktop presets. These are the numbers the daily check compares
  with (`web/perf-lighthouse.json`).
- Sizes: `gzip -9` and `brotli -q 11` (Node's zlib) of the files in `web/dist/assets` from
  `npm run build` with the engine from `make wasm`.

The application lives at `/app/basic` and `/app/pro`. `/en/app/basic` is not an application address
(`web/src/lib/public-route.ts`, `isAppPath`) and renders the public page.

What each route downloads before it is usable (gzip -9, without the HTML): the landing (`/en/`, `/es/`, `/pt/`) 382 KB, the blog post 310 KB,
`/app/basic` 4.17 MB without the engine WASM, so about 7.1 MB with it. The host serves zstd or gzip, not Brotli; with Brotli the application's
transfer would be about a third smaller.

## Biggest causes

1. **Dictionaries in the application chunk.** `src/lib/i18n/full-dictionaries.ts` registers es,
   pt and en (about 950 KB raw each) plus the steel and steps dictionaries on every application
   load. Loading only the active locale (plus English as the fallback) saves 1 to 2 MB raw. Not a
   quick win: 118 `tAt(key, locale)` call sites (sheets, PDF/DXF export, engine text) read other
   locales synchronously, so lazy dictionaries need an `await ensureLocale()` at each export entry
   point, or exported documents would silently fall back to English.
2. **One monolithic application chunk.** Everything under `src/components/pro/**`, detailing,
   design, desk, sheets and three.js is in `App-*.js`; `Viewport3D.svelte` is imported statically
   by `App.svelte`, so Basic 2D downloads three.js, KaTeX and all of PRO.
3. **WASM: 12 MB raw, built with `--no-opt`** (`scripts/wasm-cached.sh`), fetched as an ArrayBuffer
   and instantiated from bytes (`lib/engine/wasm-solver.ts`), so no streaming compile. Any
   `wasm-opt` change must pass the determinism gates first (#1072).
4. **No Brotli on the host.** Caddy `encode zstd gzip` (`infra/caddy/Caddyfile`); precompressed
   Brotli (`file_server { precompressed br gzip }`) would cut the application's transfer by about a
   third. Hashed `/assets/*` are `public, max-age=31536000, immutable` and HTML is `no-cache`, but
   **`/fonts/*` and `/favicon.svg` carry no Cache-Control** (heuristic caching only).
5. **Cloudflare Turnstile on every page** (`web/index.html`), for the feedback widget, which is
   disabled (`App.svelte`: `<!-- <FeedbackWidget /> -->`): a third-party script on the landing, the
   blog and the application for nothing. Load it when the feedback form opens.
6. **Every blog post body ships with every public page**: the ten posts of `src/lib/blog/posts/*`
   (341 KB of source) are in the entry chunk `index-*.js`, which the landing loads.
