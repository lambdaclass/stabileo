## Method

- Lighthouse 13.5.0 (CLI), Chromium for Testing (Playwright build 1248), headless, simulated
  throttling, run through `web/scripts/perf-lighthouse.mjs` (median of 3 runs per URL).
- Machine: 18-core Apple Silicon laptop under shared load (load average 11 to 22 during the runs),
  so TBT and performance scores are noisier than on an idle machine.
- Local build: `npm run build` (production, prerender included) of `origin/main` at `fe843ab8b`,
  WASM from `make wasm`.
- Sizes: `gzip -9` and `brotli -q 11` of the files in `web/dist/assets`.
- Treemap: `vite build --sourcemap` plus `source-map-explorer` 2.5.3.

application address (`web/src/lib/public-route.ts`, `isAppPath`) and renders the public page, so

uses `/app/basic` and `/app/pro`.

## Local production build: what the app downloads

| File | raw | gzip -9 | brotli 11 |
|---|---|---|---|
| `dedaliano_engine_bg-*.wasm` (solver) | 12.01 MB | 2.97 MB | 1.84 MB |
| `App-*.js` (the whole application, one chunk) | 11.91 MB | 3.67 MB | 2.67 MB |
| `App-*.css` | 0.85 MB | 123 KB | 98 KB |
| `app-mode-*.js` (shared by landing and blog) | 474 KB | 157 KB | 125 KB |
| `index-*.js` (entry) | 2.9 KB | 1.4 KB | 1.2 KB |
| `index-*.css` | 39 KB | 10 KB | 8.8 KB |

So a cold `/app/basic` transfers roughly 6.8 MB with gzip (the host serves zstd or gzip, not
Brotli; with Brotli it would be about 4.6 MB).

## Biggest causes found so far

1. **Dictionaries in the app chunk: 3.5 MB of the 11.9 MB.** `src/lib/i18n/full-dictionaries.ts`
   registers es (972 KB), pt (967 KB) and en (909 KB) plus steel and steps dictionaries in every
   app load. Loading only the active locale (plus English as the fallback) saves about 1 to 2 MB
   raw. Not a quick win: 118 `tAt(key, locale)` call sites (sheets, PDF/DXF export, engine text)
   read other locales synchronously, so lazy dictionaries need an `await ensureLocale()` at each
   export entry point or a silent fallback to English would appear in exported documents.
2. **One monolithic application chunk.** Everything under `src/components/pro/**`, detailing,
   design, desk, sheets and three.js (592 KB) is in `App-*.js`; `Viewport3D.svelte` is imported
   statically by `App.svelte`, so Basic 2D downloads three.js, KaTeX (282 KB) and all of PRO.
3. **WASM: 12 MB raw, built with `--no-opt`** (`scripts/wasm-cached.sh`), fetched as an
   ArrayBuffer and instantiated from bytes (`lib/engine/wasm-solver.ts`), so no streaming
   compile. Any wasm-opt change must pass the determinism gates first.
4. **No Brotli on the host.** Caddy `encode zstd gzip` (infra/caddy/Caddyfile); Brotli
   precompressed files (`file_server { precompressed br gzip }`) would cut the app's transfer by
   about a third. Hashed `/assets/*` are correctly `public, max-age=31536000, immutable`; HTML is
   `no-cache`. **`/fonts/*` and `/favicon.svg` carry no Cache-Control** (heuristic caching only).
   Recommendation only: infra is not changed by this PR.
5. **Cloudflare Turnstile script on every page** (`web/index.html`), loaded for the feedback
   widget, which is disabled (`App.svelte`: `<!-- <FeedbackWidget /> -->`). Third-party request on
   the landing, blog and app for nothing. Planned quick win: load it on demand in
   `FeedbackWidget.svelte`.
6. **All blog post bodies ship with the landing**: about 350 KB raw of `src/lib/blog/posts/*` in
   `app-mode-*.js`, which every public page preloads.
