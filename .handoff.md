# Inclined 2D restraint count review — 2026-11-08

Root cause: the 2D diagnostic restraint counter merged a support-frame rigid normal
and global spring axes by array slot. At π/4 a global Y spring was undercounted;
at π/2 a global X spring was double counted. The reviewed fix still used exact
floating-point equality to recognize a quarter turn and nonzero normal components,
so near-cardinal roundoff could create a spurious independent direction.

The fix counts positive global translation spring axes, then adds the inclined normal
only when a component outside their span exceeds
`8 * f64::EPSILON * max(abs(normal components))`. It uses the rotation matrix's normal
directly, without exact angle equality or angle reduction. This is a new relative
threshold for the diagnostic direction rank; no existing solver tolerance, baseline,
or assertion was loosened. The existing 1e-12 oblique cases still require independence.
No code comments were added. Rotation and hinge counting retain their existing rules.

Caller audit: this counter feeds only `compute_static_degree_2d`, then the returned
`degree`, `classification` and diagnosis. `analyze_kinematics_2d` determines
`is_solvable` independently through validation, constraint construction and stiffness
rank (or sparse factorization). The sparse path uses degree only in its returned
classification/diagnosis. Engine callers in `solver/plastic.rs` and
`solver/plastic_limit.rs` gate on `is_solvable`. The WASM export serializes the result;
`web/src/lib/engine/kinematic-2d.ts` preserves `raw.isSolvable`;
`solver-service.ts::kinematicRefusal2D` gates on that flag. Web plastic-collapse callers
also use the flag; degree is returned as diagnostic metadata. The solve action uses
classification for a success toast after solving. The separate TypeScript counting
functions are unchanged. This correction cannot allow or refuse a solve, and does
not change assembly or numerical static solutions.
