# Support-rule validation order and CI regressions — 2026-11-08

Root cause: load-session constructors ran the new support-only validator before the
ordinary input validator, and discarded initial loads before full validation. Regular
and typed paths used a different order. Prepared 3D/model guards and constrained 3D
expansion could also precede that common validation. Several older tests still encoded
the former rule that a positive spring frees a rigid 3D DOF, or relied on solved-model
quotas from before conflicting supports were refused.

The fix routes sessions through validate_input_2d/validate_input_3d before clearing
loads, validates prepared inputs before numbering/guards/expansion, and validates raw
constrained 3D input before expanding curved beams. The typed 2D path uses the same
prepared validator; typed 3D uses solve_3d. Expanded 3D models retain validation before
assembly. The support check has one position in each shared validation sequence.
A settlement on a free elastic 3D DOF remains refused, with a reason naming the spring;
conflicting rigid/spring inputs still get conflicting_support_spring first.
