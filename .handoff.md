# PR #1785 release-note follow-up

## Root cause

The 0.5.0 release notes copied the earlier statement that German, French and
Turkish were not offered and their pages opened in English. This was stale in
all six languages: `web/src/lib/i18n/locales/complete/{de,fr,tr}.ts` already export
`COMPLETE = true`, set by earlier commit `ba4e77eed`. This follow-up leaves those
flags true.

The safety comparison retained magnitudes but discarded units and minus signs.
An advisory quantity could therefore change its unit prefix, lose its unit or
become negative without failing the comparison. The translated engineering
quantities also retained English decimal points.

## Fix and files changed

- `web/src/lib/blog/posts/release-0-5-0.ts`: correct only the stale availability
  bullet in en/es/pt. The English wording proposed and applied is **“German,
  French and Turkish are offered again.”** The previous statement is factually
  wrong against the currently offered languages, so the corresponding Spanish
  and Portuguese statements were corrected too. No return date or claim of
  native-speaker approval was added.
- `web/src/lib/blog/translations/{de,fr,tr}/stabileo-0-5-0.ts`: translate that
  availability statement and use decimal commas for all six decimal quantities
  in each translation. Release versions, SA identifiers, issue numbers, code
  identifiers, URLs and already localized integer grouping remain unchanged.
- `web/src/lib/blog/__tests__/release-0-5-0-translations.test.ts`: compare
  quantities as numeric values with their signs and units attached. Normalize
  locale grouping and decimal separators, and normalize Unicode minus to ASCII
  minus while preserving explicit signs. Keep advisory IDs, issues, release
  versions and existing safety identifiers. Match versions separately from
  quantities, and distinguish signs from hyphens within words or identifiers.
  Existing comparisons still bind every advisory to its row and cell.
- `changelog.d/release-0-5-0-language-availability-quantities.md`: changelog entry.
- `.handoff.md`: this report replaces the previous task's handoff.

No engine code or calculated engineering results changed. No safety quantity in
the shipped translations changed value or unit; this strengthens the check that
would catch such a future error. No results-change document, registry entry or
new safety advisory is applicable. No tolerance, baseline or assertion was
loosened. No code comments were added.

unchecked quantity units and signs`.

**21 failed, 9 passed** in the release-translation test file. The failures were:

- Six availability statements, one for each of en/es/pt/de/fr/tr.

- Twelve negative quantity checks: a changed frequency-unit prefix, a removed

Commit B: `fix(blog): correct language availability and preserve localized signed quantities`.
Applies the fixes and removes the skip and its known-defect marker. All 30 tests
in the release-translation file pass as part of the requested targeted run.
