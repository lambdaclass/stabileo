### Changed
#### Distributed, thermal and support inputs go through unit-typed records (2026-11-08)

The 2D linear solve and every 3D engine entry point except staged construction now parse member line loads (kN/m), shell pressures (kN/m²) and edge loads (kN/m), temperature differences (°C) and expansion coefficients (1/°C), support springs (kN/m and kN·m/rad), prescribed displacements (m) and rotations (rad), the 2D support angle (rad) and the 3D member roll angle (degrees, as the wire carries it) into unit types, and the web app builds them with branded types, so assigning a rotational spring to a translational one, a line load to a force, or a radian to the roll angle no longer compiles. No result changes: the same input parses to the same bits, gives byte-identical results and the same error text, and the web app sends byte-identical JSON. Plan for the remaining slices: docs/safety/units-in-types.md.
