# Shell obstacle course

Route: `/research/benchmarks/shell-obstacle-course` (en, es, pt, de, fr, tr, hu, zh).

Belytschko et al. (1985), *Stress projection for membrane and shear locking in shell
finite elements*, CMAME 51, 221–258, DOI 10.1016/0045-7825(85)90035-0. Citation metadata
is verified by the catalogue. This page runs production MITC4 through the production
WASM wrapper; it does not implement the paper's stress-projection element.

**Status: numerically validated.** `VALIDATION.json` holds nine passing checks written by
`wasm/check.mjs` in the Research workflow. There is no `published_comparison.json`: the
article is not open access and we could not inspect its tables, so no value is attributed
to it. The roof reference 0.3024 is the normalization value of MacNeal and Harder (1985),
Table 5(a), p. 11 (checked against a scanned copy of that article; it quotes 0.3086 from
Scordelis and Lo as the theoretical value); that comparison belongs to the MacNeal–Harder
page. The cylinder reference 1.8248e−5 is inherited from the engine tests and was not
checked against a published table. The hemisphere reference 0.185 (quarter loads ±2) is the
convention of `shell_benchmark.rs::benchmark_hemisphere_hole_convergence`; MacNeal and
Harder normalize their hemisphere by 0.0940 and the native solid-shell test uses ±1 and
0.094. Those conventions are not reconciled here.

## Corrected shared models

Native `obstacle::solve` and the live page read
`engine/tests/benchmarks/shell_obstacle_course.json`. The roof and cylinder inputs are
generated by the corrected builders in `shell_benchmark.rs`; its
`research_shell_fixture_matches_corrected_builders` test holds the JSON to them (1e−12
relative, because macOS and Linux libm differ by one ulp in the mesh trigonometry).
Hemisphere inputs are unchanged. `cases` holds the browser meshes; `nativeCases` adds the
32×32 cylinder.

[#810 is a test-model correction](../../../docs/audits/810-mitc4-curved-shells.md), not an
engine failure: remove the roof's artificial crown pin, union complete symmetry constraints
at corners, and retain all tributary gravity loads. No engine source, reference or 2%
tolerance was changed.

Comparison uses signed roof u_z against −0.3024, cylinder u_y against −1.8248e−5 and
hemisphere u_x against +0.185. Wrong-direction responses fail.

## Interactive mesh

The mesh divisions N of the roof and the cylinder are a parameter from 2 to 20. For the
case-file meshes (6, 8, 12, 16) the page solves the engine-owned inputs; for any other N,
`web/src/components/research/shell1985/builders.ts` builds the same model (a TypeScript
port of `scordelis_lo_model` and `pinched_cylinder_model`) and the page solves it at once
through the production WASM wrapper. `__tests__/builders.test.ts` holds the port to every
roof and cylinder input of the case file, including the native 32×32 cylinder, at 1e−12
relative, and solves built meshes. The hemisphere keeps its three case-file meshes. The
article's "Try" links set N.

## Containment

Hemisphere 4×4, 8×8 and 16×16 results are **withheld by the engine (known issue #798,
SH-MITC4-DISTORTION)**. They stay in the denominator with null value and error, no
displacement field and `pass: false`.

## Validation checks

`wasm/check.mjs <native results directory>` runs the eleven browser cases through the
production WASM wrapper, reads the fresh native rows, keeps its earlier parity assertions,
and computes:

| Check | Observed | Tolerance | Basis |
|---|---:|---:|---|
| Roof 6×6, relative error vs −0.3024 | 1.556% | 2% | page accuracy policy (strict, direction included) |
| Roof 8×8 | 0.687% | 2% | same |
| Roof 12×12 | 0.161% | 2% | same |
| Roof 16×16 | 0.0084% | 2% | same |
| Cylinder 32×32 (native) vs −1.8248e−5 | 1.006% | 2% | same; the existing native assertion |
| Cylinder 6→8→12→16→32: largest ratio of successive errors | 0.650 | 1 (strictly below) | the error must fall with every refinement |
| WASM vs native, roof and cylinder | 0 | 1e−8 relative | the existing parity bound of this script |
| Hemisphere meshes not withheld by both runtimes with #798 | 0 | 0 | containment must hold in both runtimes |
| Browser builders vs every case-file input | 1.2e−16 | 1e−12 relative | the bound of the engine's fixture test |

The 2% limit is the policy of Stabileo's benchmark pages (it coincides with grade A of
MacNeal and Harder, p. 14), not a tolerance from Belytschko et al. Cylinder 6×6 to 16×16
miss it (37.9%, 24.6%, 12.0%, 6.8%); those are accuracy failures, shown on the page as
failures, and are not validation checks. The convergence check is what the coarse cylinder
meshes are validated for.

With `--write` the script writes `VALIDATION.json`, `reference-results/references.json`
(the three references with their provenance, read from the case file) and
`reference-results/MANIFEST.json`. Without it the script recomputes everything and fails
if a check fails or the committed files differ (same ids, metrics, tolerances and verdicts;
observed values within 1e−9 relative).

## Reproduction

From the repository root:

```sh
SHELL_OBSTACLE_RESULTS=/tmp/shell-native cargo test --locked --release --manifest-path engine/Cargo.toml --test validation benchmark_scordelis_lo
(cd web && npm ci && npm run wasm)
node research/benchmarks/shell-obstacle-course/wasm/check.mjs /tmp/shell-native
(cd web && npx vitest run src/components/research/shell1985)
```

Any one of the shell tests writes every native row, because the fixture reader solves all
cases once. Add `--write` to the `check.mjs` line to regenerate the evidence. Browser spec:
`web/e2e/research-shell-obstacle-course.spec.ts`.

Research, not a design tool.
