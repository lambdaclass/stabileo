# Four-cable forward form-finding

Pastrana, Oktay, Bletzinger, Adams & Adriaenssens (2026), *Differentiable force density
method for the design of lightweight structures*, CMAME 458, 118783.
https://doi.org/10.1016/j.cma.2026.118783

## Scope and choice

One example: the four-bar pin-jointed topology in Section 2.1, Fig. 2, evaluated as a
positive-density cable net using Eq. (7). This is deliberately small: an exact solution,
an independent reference-code run and a production-engine check are all possible.
It demonstrates the forward kernel, not the paper's differentiable inverse-design contribution.
Effort/impact: small forward implementation, exact validation, useful geometry handoff;
visual impact is modest compared with the paper's optimized roofs.

The article gives the topology and analytical equation; **our numerical inputs are chosen here**.
No dimensions were inferred from the illustration. Supports are (±2, ±2, 0) m, one free
node starts at the origin, four positive densities are 1 kN/m, and the central load is
(0, 0, −4) kN. The exact result is (0, 0, −1) m, four lengths of 3 m and four tensions
of 3 kN. These are equation-derived targets, not numbers reported by the paper.

The article's Crossref licence is CC BY-NC 4.0. All prose and graphics here are our own;
no paper text or figures are copied. The gallery thumbnail is generated from our Rust results.

## Independent reference

`reference/run_reference.py` calls the **unmodified installed** `jax_fdm.fdm` implementation
(`sparse=False`, float64), pinned at `9a17fd379071fb3511ca914f46e8d1e8c286460e`.
The MIT licence was read before running. No author implementation is vendored or adapted.
The publication's exact code revision is unknown. The wrapper defines our inputs and exports
positions and forces; it does not replace any reference calculations.

Download the pinned source archive from
https://codeload.github.com/arpastrana/jax_fdm/tar.gz/9a17fd379071fb3511ca914f46e8d1e8c286460e
into a scratch directory, inspect its licence and source, and install in an isolated Python
3.12 environment. `reference-results/MANIFEST.json` records the archive SHA-256, exact installed
package versions, interpreter/platform and output checksums. Run from this directory:

```
/path/to/isolated/python -I reference/run_reference.py reference-results /path/to/source.tar.gz
```

The five `(q, downward load)` cases are `(1,4)`, `(0.5,4)`, `(2,4)`, `(1,1)`, `(1,8)` in
kN/m and kN. Their free-node elevations are −1, −2, −0.5, −0.25 and −2 m.
Force references are in `reference-results/four_bar.json`.

## Rust and browser reproduction

This is an independent Cargo workspace depending on the engine as a library. The reusable
`Net` solver supports positive-density networks, checks anchoring and input dimensions, assembles
the reduced equilibrium matrix and uses engine sparse Cholesky for all three coordinates.
No numerical behaviour in `engine/src` is changed.

From the repository root, inside the pinned Nix environment:

```
cargo test --locked --manifest-path research/form-finding/pastrana-2026/Cargo.toml
cargo test --locked --manifest-path research/form-finding/pastrana-2026/wasm/Cargo.toml
cargo run --locked --manifest-path research/form-finding/pastrana-2026/Cargo.toml --bin reproduce -- research/form-finding/pastrana-2026/results/stabileo_results.json
WRITE_VALIDATION=1 cargo test --locked --manifest-path research/form-finding/pastrana-2026/Cargo.toml
research/form-finding/pastrana-2026/wasm/build.sh
node research/form-finding/pastrana-2026/wasm/check.mjs web/public/research-wasm/pastrana-2026
python3 -I research/form-finding/pastrana-2026/reference/thumbnail.py
```

`make research.wasm` builds this separate browser bundle as well as the shared viewer.
The route is `/research/form-finding/pastrana-2026` (with the site's locale prefix).
The worker can be terminated with Stop; failed requests retain and label the previous result.
The replay consists of 25 independently equilibrated loads from 1 to 4 kN at q = 1 kN/m,
not solver convergence iterations. Rust tests compare every replay frame with the solver.

## Evidence and the product link

`VALIDATION.json` is generated by the Rust validation test. Thirty numerical comparisons cover
all coordinates, cable forces, free-node residual, Eq. (7), production truss forces and the exact
linear elastic displacement over five cases. Absolute tolerances: 1e-12 m for coordinates and
displacements; 1e-12 kN for FDM forces/residual; 1e-9 kN for production-engine forces.
Additional tests exercise unequal densities, several free nodes, invalid/unanchored networks,
and replay reproducibility. Browser WASM is checked separately against the same closed forms.

The found geometry opens as a **3D truss**, E = 200000 MPa, A = 0.001 m², density zero,
all support translations fixed, with the same central load. `solve_3d` is invoked in the
Rust tests on this same model. Symmetry and equal member stiffnesses make its axial forces
match FDM. For h = P/(4q), L = sqrt(8+h²) and EA = 200000 kN, its linear elastic displacement
is uz = −P L³/(4 EA h²); the baseline is −0.000135 m.

This is a **separate initially unstressed elastic analysis**, not an equilibrated prestressed
cable model. No prestress, cable slackening or geometric stiffness is transferred. Agreement
for this symmetric case does not establish agreement for arbitrary nets.

`PUBLISHED_COMPARISON.json` explicitly records that published numerical results are **not**
reproduced. It identifies the section/figure/equation used without turning derived values into
published observations. Catalogue status must not claim published-figure agreement or full DFDM.

## Limits

No adjoints/gradients, inverse optimization, shells, mixed signs, pressure/self-weight updates,
nonlinear elastic cables, buckling, published optimized geometries or performance comparisons.
The shared scalar viewer shows labelled projections; the editor preserves all 3D coordinates.
Agreement with reference software is not experimental validation or certification.
Research, not a design tool.

## Review round 2 (2026-10-30)

Reviewers: kimi, codex, claude. All confirmed should-fix findings addressed; production engine
numerics and acceptance tolerances unchanged. Committed validation is now compared with fresh
results (metric, count, tolerance and pass flag exact; observed errors within 32 float64 epsilons
at unit scale for cross-platform roundoff). Every replay load, density, node, edge, force and
residual is checked. The decoded editor payload is solved through the production WASM input
builder, including its pinned supports, material, section and all signed member forces.

Tolerance rationale: coordinates/lengths are about 3 m, forces about 3–12 kN and EA = 200000 kN.
Float64 epsilon is 2.22e-16. The 1e-12 coordinate/FDM budget leaves several hundred operations
of assembly/factorization roundoff at these scales. Elastic force recovery multiplies small
relative displacements by large stiffness and permits cancellation; 1e-9 kN is a conservative
absolute recovery budget (roughly 1e-10 relative), not a relaxed FDM criterion. Displacement
checks remain 1e-12 m. Evidence roundoff comparison is far tighter than these acceptance limits.

The pinned public source archive is available in the reference scratch environment. Its examples
include larger cable nets, arches and gridshells, but no identifiable Fig. 2 numerical dataset.
The committed reference and published-comparison evidence therefore remain explicitly about
our chosen inputs, Eq. (7), and jax_fdm, not paper figure agreement. The live page states that
comparison directly and contains no author questions or pending comparison badges.

Research translations are explicitly scoped to English, Spanish and Portuguese; every public
locale is tested, and other locale routes identify their research content as English.
Browser regressions cover restart from the middle, validation recovery, status announcements,
failed WASM requests retaining the labelled result, and responsive targets/text/viewer position.
Playwright execution is unavailable in this environment.
